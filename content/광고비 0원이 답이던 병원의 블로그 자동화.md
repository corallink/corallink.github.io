어느 안과의 시력교정 환자가 1년 남짓 동안 200명 가까이 들어왔는데, 그중 광고로 들어온 사람은 사실상 0명이었습니다. 나는 개발자가 아니지만, 이 병원의 블로그 주제 고르는 일을 웹앱으로 자동화했습니다.

## 시작은 숫자 하나였다

지방의 한 안과를 컨설팅하면서 내원 동기를 뜯어봤습니다. 시력교정(라식·라섹·드림렌즈)으로 1년 남짓 동안 200명 가까이. 적지 않은 숫자입니다. 그런데 광고 효율(ROI)을 보니 사실상 0이었습니다. 돈을 쓴 만큼 환자가 안 들어왔다는 뜻입니다.

대신 진짜 엔진은 두 개였습니다. 하나는 수술받은 사람이 데려온 소개 환자(절반 안팎). 다른 하나는 온라인에서 검색하다 들어온 환자(3분의 1 안팎). 광고를 늘릴 게 아니라, 이 두 축을 두껍게 만드는 게 맞았습니다.

온라인 축의 핵심은 블로그입니다. 네이버에서 "지역명+라식" 같은 키워드로 검색했을 때 이 병원 글이 위에 떠야 합니다. 그런데 매주 블로그 주제를 고르는 방식이 문제였습니다. 데이터(어떤 글이 조회수가 높은지, 어떤 키워드가 몇 위인지)는 분명히 있는데, 정작 주제는 감으로 정하고 있었습니다.

## 나는 코드를 못 쓴다. 그래도 만들었다

여기서 보통 "개발자한테 맡겨야지" 하고 멈춥니다. 나는 비개발자·비디자이너입니다. 그런데 막힌 지점이 명확했습니다. **데이터는 있는데 주제 선정에 안 쓰입니다.** 이건 사람을 더 쓰는 문제가 아니라 흐름을 자동화하는 문제였습니다.

코드를 못 쓰는 내가 웹앱을 만든 방식은 이렇습니다. 내가 한 일은 "어떤 데이터를 받아서 어떤 규칙으로 주제를 추천해야 하는가"를 말로 또박또박 정리하는 것이었고, 그 설계를 AI에게 주면 AI가 화면과 동작을 코드로 옮겼습니다. 막히면 다시 말로 고치고, AI가 다시 짜는 식의 반복이었습니다. 그렇게 나온 웹앱의 흐름은 이렇습니다.

- 네이버 블로그 통계를 화면에서 복사해 붙여넣으면, 발행글 30개를 자동으로 정리합니다.
- 버튼 한 번에 17개 키워드의 네이버 순위를 측정합니다 (12주치를 쌓아 추세를 봅니다).
- 이 데이터로 "11위 밖이라 밀린 키워드 먼저, 조회수 높은 카테고리에 가중치"라는 규칙을 돌려 주제 10개를 추천합니다.
- 카드를 하나 고르면 AI가 초안까지 자동으로 써줍니다.

여기서 분업이 분명합니다. AI는 데이터를 정리하고, 규칙대로 주제를 추리고, 초안을 깔아 줍니다. 사람은 추천 10개가 이 병원 맥락에 맞는지, 초안이 의료광고 경계를 넘지 않는지를 검수하고 판정합니다. 자동화한 건 '판단'이 아니라 '판단 앞까지의 준비'입니다.

핵심은 **주제 선정이 '감'에서 '규칙'으로 바뀐 것**입니다. 매주 똑같이 고민하던 일이, 데이터를 보고 정해지는 일이 됐습니다.

## 막힌 곳과 우회로

순탄하진 않았습니다. 네이버 블로그 통계는 깔끔한 데이터로 주는 통로가 없었습니다. 처음엔 화면을 자동으로 긁어오려 했지만 불안정해서 버렸습니다. 대신 사람이 30개를 30초간 복붙하는 걸 받아들이고, **그 다음부터를 전부 자동화**했습니다. 완벽한 자동화에 매달리다 아무것도 못 만드는 것보다, 30초의 수작업을 인정하고 나머지를 푸는 쪽이 빨랐습니다.

데이터를 어디 저장할지도 한참 헤맸지만, 클라우드 저장소 토큰을 발급받아 정착시켰습니다. 막히면 우회로 먼저, 완벽한 길은 나중에. 이게 내가 도구를 끝까지 만들어내는 방식입니다.

## 주제 선정에 AI를 이렇게 적용했습니다

코드를 못 쓰는 내가 한 일은, 규칙을 말로 또박또박 정리한 것뿐입니다.

| 단계 | 하는 일 |
|---|---|
| 준비 | "어떤 데이터를 받아 어떤 규칙으로 주제를 추천하는가"를 말로 정리합니다 |
| 입력 | 그 설계를 AI에게 주고, 네이버 통계와 순위 데이터를 화면에 붙여넣습니다 |
| 요청 | "11위 밖 키워드 먼저, 조회수 높은 카테고리에 가중치를 줘 주제 10개를 추천해 줘" |
| AI가 하는 일 | 데이터 정리 + 규칙대로 주제 추림 + 초안 깔기 (막히면 말로 고쳐 다시 짬) |
| 사람이 하는 일 | 추천이 병원 맥락에 맞는지, 초안이 의료광고 경계를 넘지 않는지 검수·판정 |

자동화한 건 '판단'이 아니라 '판단 앞까지의 준비'입니다.

## 왜 이 이야기를 남기나

AI 시대엔 기록이나 정리는 누구나 무한히 찍어냅니다. 차별화가 안 됩니다. 복제가 안 되는 건 "내가 실제로 무엇을 만들어 무엇을 바꿨는가"라는 빌드 스토리뿐입니다.

내가 파는 건 코드 실력이 아닙니다. **병원의 진짜 병목을 숫자로 찾아내고(광고 효율은 사실상 0, 소개·온라인이 엔진), 그걸 도구로 풀어내는 일**입니다. 개발자가 아니어도, 문제가 선명하면 만들 수 있습니다. 거창한 웹앱이 아니어도, 가진 데이터 한 장을 AI에게 주고 "이 규칙으로 다음에 쓸 주제를 추천해 달라"고 말하는 것에서 시작하면 됩니다.
